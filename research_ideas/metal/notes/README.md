## Workflow
1. Brainstorm in `01`-`04`.
2. Commit decisions to `05_research_plan.md`.
3. Use `06_scene_paper_skeleton.md` as the markdown-first paper object when the scene branch is
   active.
4. Expand into `07_scene_paper_memo.md` before opening a LaTeX workflow.
5. Expand into `08_scene_paper_sections.md` for first full-draft prose.
6. Use `09_band_success_workflow.md` for the scene-to-band-success sidecar branch.
7. Use `10_workflow_reset.md` when the project needs a clean reset around the main paper.
8. Use `11_band_upgrading_ladder.md` when the sidecar is reframed as cohort upgrading rather than
   naive band-level success.
9. Use `12_scene_diffusion_workflow.md` for exploratory scene-to-scene diffusion and animated map
   ideas.
10. Use `13_band_world_animation_workflow.md` for the band-level world animation branch.
11. Use `14_scene_diffusion_exposure_panel.md` for the first serious hub-exposure diffusion panel.
12. Use `15_multi_genre_diffusion_check.md` for the first cross-genre diffusion comparison.
13. Use `16_digital_era_split_probe.md` for the broad early/transition/mature digital robustness
    check on the preferred scene regression.
14. Use `17_lit_review_verification.md` as the source crosswalk behind the LaTeX literature-review
    section.
15. Use `18_city_broadband_data.md` for the recent-period city broadband build and data notes.
16. Use `19_early_broadband_shock_memo.md` for the current read on broadband-shock feasibility.
17. Use `20_top_five_strategy_review.md` for the strategic overview, branch ranking, and
    upload-ready external review prompt.
18. Use `21_oracle_math_model_draft.md` for model-language drafting and equation framing around the
    live scene-emergence paper.
19. Use `22_causal_followon_designs.md` for the ranked strategy memo on quasi-causal follow-on
    papers distinct from the current reduced-form draft.
20. Use `23_breakout_demand_shock_design.md` for the first concrete estimand and specification note
    for the breakout-demand follow-on branch.
21. Use `24_breakout_episode_screen.md` for the first screened list of branch-ready breakout events
    before building a stacked event-study file.
22. Use `25_breakout_branch_workflow.md` for the ordered branch workflow once the event screen is
    locked.
23. Use `26_breakout_candidate_audit.md` for the live operational audit that distinguishes retained
    first-breakout events from parked flat-capability rows and later repeats.
24. Use `27_breakout_peak20_relaxed_extension.md` for the secondary `peak <= 20` branch extension
    after the strict top-10 stack proves too thin.
25. Use `28_breakout_seed_recovery_targets.md` for the ranked list of missing home-market recoveries
    that could still change the relaxed first-breakout branch.
26. Use `29_breakout_branch_parking_memo.md` for the stop/go rule after the final bounded
    recovery pass on the breakout-demand branch.
27. Use `30_central_musician_loss_first_pass.md` for the first feasibility audit on death or exit
    shocks to highly central local musicians.
28. Use `31_causal_channel_reassessment.md` for the ranked causal-channel reassessment after the
    death, breakout, broadband, and main-result strengthening passes.
29. Use `32_external_arrival_first_pass.md` for the experienced outside-musician arrival workflow
    and its own-band-excluded final audit.
30. Use `33_data_recovery_forensics.md` for the data-loss and recovery record.
31. Use `34_external_arrival_robustness_verdict.md` for the first robustness gate and sidecar
    promotion decision.
32. Use `35_journal_target_and_polish_workflow.md` for the target-journal and next paper-polish
    workflow.
33. Sync next tasks in `STATUS.md`.
